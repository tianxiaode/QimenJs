## 主要完成

### 1. StateLocalMutationAbility 修复

**问题**：`StateLocalMutationAbility` 中 `this.host` 访问不正确，导致无法访问 `schema` 和 `state` 等属性。

**修复内容**：

| 修改 | 说明 |
|------|------|
| 使用闭包捕获 `this` | 在 `expose()` 中使用 `const self = this`，方法中用 `self` 访问 Ability 实例属性 |
| `self.host` 访问 State 实例 | 通过 `self.host as IBaseEntityState` 访问 `schema`、`sourceData` 等 |
| `changes` 改为 getter | 从 `this._changes` 动态派生，确保始终返回最新状态 |

### 2. SchemaRegistrar 延迟编译

**问题**：Schema 编译逻辑分散在 `SchemaAbility`（Manager 侧）中，State 侧无法复用。

**修复内容**：

| 修改 | 说明 |
|------|------|
| `register(schema)` 使用 `schema.name` 作为 key | 不再需要单独传 key，减少冗余 |
| `register(name, fields)` 注册字段组 | 保持字段组注册方式不变 |
| `getCompiled(key)` 延迟编译 | 第一次调用时编译并缓存，避免启动时集中编译 |
| 重复注册同名 Schema 输出警告 | 防止意外覆盖 |
| 从 `SchemaAbility` 移植编译逻辑 | `compileSchema`、`processFieldBatch`、`extractRule`、`ensureTreeDefaults` |

**设计决策**：

- Schema 集中注册到 SchemaRegistrar，Manager 通过 `schemaKey` 获取
- 编译工作全部在 SchemaRegistrar 内部完成（延迟编译 + 缓存）
- Manager 的 `schema` 改为 getter，返回 `SchemaRegistrar.getCompiled(this.schemaKey).schema`
- State 通过 `this.host.schema` 访问（即 Manager 的 schema getter）

## 关键技术决策

### 1. Schema 延迟编译

**背景**：ABP 框架中很多表都有重复字段（如 `createdAt`、`updatedAt`），SchemaRegistrar 的目的是注册全部 Schema 结构，在第一次获取时编译。

**决策**：
- Schema 集中注册到 SchemaRegistrar
- Manager 使用 `schemaKey` 从注册表获取
- 编译工作全部放注册表，延迟编译 + 缓存
- Manager 的 `schema` 改为 getter，返回编译后的 Schema
- State 通过 `this.host.schema` 访问

### 2. 取消 IEntity 泛型

**背景**：`IEntity` 本身有 `[key: string]: any`，`T extends IEntity` 没有提供额外类型安全。Schema 和 IUser 重复定义问题也无法通过泛型解决。

**决策**：取消 `T extends IEntity` 泛型参数，统一使用 `IEntity`。如果业务代码需要更精确的类型，可以单独定义接口。

## 待解决问题

### 1. entity 包目录结构重组

当前 `abilities/` 目录中 Manager 能力和 State 能力混在一起，需要按以下方式重组：

```
src/entity/abilities/
├── manager/          # Manager 专用能力
│   ├── local/        # 本地实体能力
│   └── remote/       # 远程实体能力
└── state/            # State 专用能力
    ├── base/         # 基础能力（Schema、Cache、Dirty）
    ├── search/       # 搜索能力（平面搜索、树搜索）
    ├── mutation/     # 变更能力
    └── tree/         # 树能力
```

### 2. BaseEntityState 不应包含搜索能力

BaseEntityState 应该只包含基础能力（Schema、Cache、Dirty），搜索能力应该在具体 State 类中添加：
- `FlatLocalEntityState` → `StateSearchAbility`（平面搜索）
- `TreeRemoteEntityState` → `TreeSearchAbility`（树搜索）

### 3. SchemaAbility 迁移

Manager 侧的 `SchemaAbility` 编译逻辑已移到 `SchemaRegistrar`，需要：
- 简化 `SchemaAbility` 为代理模式
- 或者删除 `SchemaAbility`，Manager 直接使用 `SchemaRegistrar.getCompiled()`

### 4. StateSchemaAbility 简化

State 侧的 `StateSchemaAbility` 应简化为代理模式，通过 `this.host.schema` 访问。
