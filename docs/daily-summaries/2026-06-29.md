## 主要完成

### 1. AbilityBase `this` 绑定问题彻底修复

**问题**：`AbilityBase.precompile()` 创建临时实例调用 `expose()`，闭包中的 `this` 指向临时实例而非真正的 Ability 实例。箭头函数的 `this` 是词法绑定，`call()`/`bind()`/`apply()` 均无法改变。这导致所有 Ability 闭包中 `this.host` 始终为 `null`，是系统性 bug。

**解决方案**：引入 `AbilityProxy` 代理对象，彻底绕开 `this` 指向问题。

| 机制 | 说明 |
|------|------|
| `AbilityProxy` 接口 | `{ host: THost, self: TSelf }`，`host` 为宿主，`self` 为 Ability 实例 |
| `expose(proxy)` | 子类实现，闭包通过 `proxy.host`/`proxy.self` 访问，不依赖 `this` |
| `proxy.host` getter | 从 `sharedHostRef` 读取值，支持多实例隔离 |
| getter/setter | 执行时临时切换 `sharedHostRef`，确保多宿主实例互不干扰 |
| 方法 | `bind(host)` 绑定，`this` 就是宿主，`this.host` 通过 ComposableBase getter 返回宿主自身 |
| `ComposableBase.host` getter | `get host() { return this; }`，统一 getter/setter 和方法中的宿主访问写法 |

**访问规则**：

| 场景 | 宿主访问 | Ability 私有属性 |
|------|----------|-----------------|
| getter/setter | `proxy.host` | `proxy.self._xxx` |
| 方法（普通函数） | `this.host`（ComposableBase getter） | `proxy.self._xxx` |
| 方法（箭头函数） | `proxy.host` | `proxy.self._xxx` |

## 待解决问题

### 1. StateSchemaAbility 简化

当前 `StateSchemaAbility` 为每个 schema 属性（`idField`, `idType`, `nameField`, `searchFields`, `isTree` 等 15 个）分别定义 getter，每个 getter 都重复执行 `proxy.host as IBaseEntityState`。应简化为：
- 直接暴露 `schema` getter，返回 `proxy.host.schema`
- 或者像 Manager 侧的 `SchemaAbility` 一样，聚合为 `schemaKeys`/`schemaTree` 等分组 getter

### 2. entity 包测试覆盖不足

当前仅有 2 个测试文件：
- `FlatLocalEntityState.test.ts` — 覆盖本地平面状态
- `SchemaGetter.test.ts` — 覆盖 Schema getter

缺少：
- `FlatRemoteEntityState` 测试
- `TreeRemoteEntityState` 测试
- Manager 各能力测试（LocalList, LocalGet, RemoteCreate, RemoteUpdate 等）
- ComposableBase + AbilityBase 集成测试

### 3. Ability 实例共享问题

`ComposableRegistrar` 缓存了 Ability 实例，所有宿主实例共享同一个 Ability 实例。这意味着：
- Ability 的私有属性（如 `_changes`、`_deleteSnapshots`）在多个宿主实例间共享
- `ability.host` 在多实例场景下不稳定
- 当前通过 `hostRef` 闭包隔离解决了 getter/setter 的多实例问题，但 Ability 私有方法仍依赖 `this.host`

**可能的解决方案**：
- 每个宿主实例创建独立的 Ability 实例（放弃缓存）
- Ability 私有方法全部通过参数接收 host（当前部分已实现）

### 4. DebounceAbilityBase 适配

`DebounceAbilityBase` 是抽象类，不直接实现 `expose()`，但子类需要使用 `proxy`。需要确认所有 DebounceAbilityBase 子类已正确适配。
