## 技术决策

### 1. 纯粹的职责分离
- HTTP 包只负责 HTTP 通信
- Entity 包只负责数据处理
- 不再混合在一起

### 2. 统一的上下文
- 使用 RequestContext 作为统一上下文
- 所有处理器都操作同一个上下文

### 3. 自动注册机制
- actions 在模块加载时自动注册
- 无需手动调用注册函数

### 4. 简化的 API
- 移除不必要的复杂性
- 只提供必要的功能

## HTTP Actions 管道流程

```
1. PREPARE (准备阶段 - 100)
   └─ CommonParamsEnricher (合并公共参数)
   └─ UrlBuilder (构建 URL)

2. EXCHANGE (交换阶段 - 200)
   └─ FetchTransport (Fetch 传输)
   └─ XhrTransport (XHR 传输)

3. PROCESS (处理阶段 - 300)
   └─ ResponseAnalyzer (响应分析)
   └─ DataParser (数据解析 - raw → JSON)

4. ALIGN (对齐阶段 - 400)
   └─ DownloadInterceptor (下载拦截)
```
