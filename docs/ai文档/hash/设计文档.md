# FileHashCalculator 设计文档

## 1. 概述

### 1.1 项目背景
开发一个专注于大文件哈希计算的JavaScript库，主要用于断点续传场景。核心需求是能够高效、安全地计算大文件的哈希值，支持进度反馈、暂停/恢复和取消操作。

### 1.2 设计目标
- 🎯 **最小依赖**：不内置算法，用户传入所需算法
- 🎯 **大文件友好**：流式分片处理，避免内存溢出
- 🎯 **高性能**：Worker池并行计算
- 🎯 **用户体验**：实时进度反馈，支持暂停/恢复
- 🎯 **安全性**：避免eval，安全执行用户算法

## 2. 核心设计

### 2.1 架构图
```
用户代码
    ↓
FileHashCalculator (主控制器)
    ├── FileChunkReader (文件分片读取器)
    ├── AlgorithmWorkerPool (算法Worker池)
    └── ResultAggregator (结果聚合器)
    ↓
哈希结果 + 分片哈希列表
```

### 2.2 数据流
```
File → 分片读取 → Worker计算 → 结果聚合 → 最终哈希
        (流式)     (并行)      (收集)      (拼接+哈希)
```

## 3. 组件设计

### 3.1 FileHashCalculator（主控制器）
**职责**：协调整个计算流程，对外提供API

**主要接口**：
```typescript
class FileHashCalculator {
  constructor(
    algorithm: (chunk: ArrayBuffer) => string | Promise<string>,
    options?: {
      chunkSize?: number;      // 默认1MB
      maxWorkers?: number;     // 默认CPU核心数，最多4个
    }
  );
  
  // 计算文件哈希
  async compute(
    file: File,
    onProgress?: (progress: Progress) => void
  ): Promise<HashResult>;
  
  // 控制方法
  pause(): void;
  resume(): void;
  cancel(): Promise<void>;
}
```

### 3.2 FileChunkReader（文件分片读取器）
**职责**：流式读取文件并分片

**实现要点**：
- 使用`File.slice()`分片读取，避免全文件加载到内存
- 支持暂停/恢复：记录已读取位置
- 异步迭代器模式：`for await (const chunk of reader)`

**默认分片策略**：
- 分片大小：1MB（1048576字节）
- 内存缓冲：最多缓存2个分片（读取-计算流水线）

### 3.3 AlgorithmWorkerPool（算法Worker池）
**核心创新**：动态创建包含用户算法的Worker

**Worker创建流程**：
```javascript
// 1. 构建Worker代码模板
const workerCode = `
  // 用户算法（从主线程传入）
  const userAlgorithm = ${algorithm.toString()};
  
  // Worker消息处理
  self.onmessage = async (e) => {
    const result = await userAlgorithm(e.data.chunk);
    self.postMessage({ hash: result, taskId: e.data.taskId });
  };
`;

// 2. 创建Blob Worker
const blob = new Blob([workerCode], { type: 'application/javascript' });
const worker = new Worker(URL.createObjectURL(blob));

// 3. 管理Worker生命周期
```

**Worker池管理**：
- 池大小：`Math.min(navigator.hardwareConcurrency || 4, 8)`
- 任务队列：空闲Worker立即执行，无空闲则排队
- 错误处理：Worker崩溃自动重启
- 资源清理：计算完成后释放Blob URL

### 3.4 ResultAggregator（结果聚合器）
**职责**：收集分片哈希，计算最终结果

**聚合策略**：
```typescript
// 简单可靠的聚合方式
async function aggregate(chunkHashes: Array<{index: number, hash: string}>) {
  // 1. 按索引排序
  chunkHashes.sort((a, b) => a.index - b.index);
  
  // 2. 拼接所有分片哈希
  const combined = chunkHashes.map(c => c.hash).join('');
  
  // 3. 对拼接结果再次哈希（确保最终哈希固定长度）
  const finalHash = await algorithm(new TextEncoder().encode(combined));
  
  return {
    totalHash: finalHash,
    chunkHashes: chunkHashes.map(c => ({
      index: c.index,
      hash: c.hash,
      offset: c.index * chunkSize,
      size: c.size
    }))
  };
}
```

### 4.1 进度反馈

```typescript
interface Progress {

```

### 4.2 暂停/恢复机制
```typescript
class PausableController {
  private isPaused = false;
  private pausePromise: Promise<void> | null = null;
  private resumeResolve: (() => void) | null = null;
  
  async pause() {
    this.isPaused = true;
    this.pausePromise = new Promise(resolve => {
      this.resumeResolve = resolve;
    });
  }
  
  resume() {
    this.isPaused = false;
    this.resumeResolve?.();
    this.pausePromise = null;
  }
  
  async waitIfPaused() {
    if (this.isPaused && this.pausePromise) {
      await this.pausePromise;
    }
  }
}
```

### 4.3 取消机制
```typescript
class CancellableTask {
  private isCancelled = false;
  private cancelSignal = { cancelled: false };
  
  cancel() {
    this.isCancelled = true;
    this.cancelSignal.cancelled = true;
    
    // 清理操作：
    // 1. 停止文件读取
    // 2. 清空任务队列
    // 3. 终止Worker中的任务
    // 4. 释放资源

  checkCancelled() {
```

### 4.4 错误处理策略
**错误分类**：
1. **文件读取错误**：重试当前分片（最多3次）
2. **Worker计算错误**：重启Worker并重试任务
3. **内存不足错误**：减小分片大小或减少并发数
4. **用户取消**：优雅终止，清理资源

## 5. 性能优化

### 5.1 内存优化
- **流式处理**：不将整个文件加载到内存
- **分片缓存**：最多缓存2个分片（读取-计算流水线）
- **及时清理**：计算完成后立即释放内存

### 5.2 CPU优化
- **Worker池**：充分利用多核CPU
- **任务调度**：智能任务分发，避免Worker空闲
- **小文件优化**：小于分片大小的文件直接在主线程计算

### 5.3 网络优化（如果支持URL文件）
- **范围请求**：支持从URL流式读取
- **断点续传**：记录已计算分片，避免重复计算

## 6. 安全考虑

### 6.1 算法执行安全
- **无eval**：算法代码直接嵌入Worker
- **沙箱环境**：算法在Worker隔离环境中运行
- **资源限制**：限制算法执行时间和内存

### 6.2 数据安全
- **不持久化**：计算完成后清理所有数据
- **内存清理**：显式释放ArrayBuffer引用
- **URL清理**：及时revokeObjectURL

## 7. API设计

### 7.1 主要API
```typescript

const calculator = new FileHashCalculator(
  (chunk) => xxhash64(chunk, { seed: 0 }),
  { chunkSize: 2 * 1024 * 1024 }
);

  console.log(`进度: ${progress.percentage}%`);

// 控制计算
calculator.pause();
calculator.resume();
await calculator.cancel();
```

### 7.2 返回结果结构
```typescript
interface HashResult {
  // 最终哈希（用于文件唯一标识）
  totalHash: string;
  
  // 分片哈希列表（用于断点续传验证）
  chunkHashes: Array<{
    index: number;      // 分片索引
    hash: string;       // 分片哈希
    offset: number;     // 在文件中的偏移量
    size: number;       // 分片大小
  }>;
  
  // 元数据
  metadata: {
    fileSize: number;
    chunkSize: number;
    chunkCount: number;
    algorithm: string;   // 算法标识
    timeCost: number;    // 总耗时(ms)
    checksum?: string;   // 可选：校验和
  };
}
```

## 8. 使用示例

### 8.1 基本使用
```typescript
import { xxhash64 } from '@orbitjs/crypto';

// 创建计算器
const hasher = new FileHashCalculator(
  (chunk) => xxhash64(chunk),
  { chunkSize: 4 * 1024 * 1024 } // 4MB分片
);

// 选择文件
const file = document.getElementById('file-input').files[0];

// 计算哈希
const result = await hasher.compute(file, (progress) => {
  console.log(`${progress.processedBytes}/${progress.totalBytes} bytes`);
});

// 使用结果
console.log('文件哈希:', result.totalHash);
console.log('分片数量:', result.chunkHashes.length);
```

### 8.2 断点续传场景
```typescript
// 上传前计算文件特征值
const fileHashResult = await hasher.compute(file);

// 将分片哈希发送到服务器
await api.initUpload({
  fileHash: fileHashResult.totalHash,
  fileSize: file.size,
  chunkHashes: fileHashResult.chunkHashes
});

// 上传分片时，服务器可以验证分片哈希
```

### 8.3 高级控制
```typescript
// 带控制的计算
```

## 10. 限制与注意事项

### 10.1 技术限制
- **浏览器兼容性**：需要支持File API和Web Worker
- **文件大小限制**：受浏览器内存限制
- **Worker限制**：部分浏览器有Worker数量限制

### 10.2 使用建议
1. **分片大小选择**：
   - 小文件（<10MB）：直接计算
   - 中等文件（10MB-100MB）：1MB分片
   - 大文件（>100MB）：2-4MB分片

2. **Worker数量**：
   - 默认使用CPU核心数
   - 内存紧张时减少Worker数

3. **内存监控**：
   - 监控内存使用
   - 大文件计算时提示用户
