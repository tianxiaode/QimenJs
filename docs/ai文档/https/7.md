你提到的情况是非常关键的，**状态码不是200时，也需要错误处理**，而错误处理的复杂性确实在于它的多样性。错误处理不仅仅是判断状态码，还需要根据不同的响应结构来解析错误信息，同时可能还需要与系统的自定义错误逻辑对接。

在这种情况下，我们需要将错误处理做得更细化，并且让错误的判断与解析流程更加统一。我们可以通过统一的错误处理机制来简化这个复杂度，同时保证代码的可扩展性和灵活性。

### 设计思路

1. **状态码判断**：状态码不是200时，不仅需要返回错误，还要根据后端的错误结构进行解析。可能有的接口会返回2xx的状态码，但实际上是业务错误，或者即使状态码不是200，也会返回正常的数据结构，因此状态码的判断和错误解析是分开的。

2. **统一错误处理**：错误的处理不应该只是通过状态码来判断错误，而是应该通过统一的错误解析管道来处理。这意味着无论是状态码错误，还是业务逻辑错误，最终都应该通过统一的 `ErrorParser` 机制进行解析。错误处理的复杂性也在这里——不同系统的错误格式不一样，但它们都应该有一个统一的解析接口。

3. **重叠部分**：状态码和错误解析之间存在一定的重叠。状态码不是200时直接进入错误解析，但在管道中也可能继续解析错误信息。为了避免重叠部分，我们可以将错误处理分为两个阶段：

   * **初步错误处理**：检查状态码，如果不是200则认为是错误，直接进入错误处理。
   * **详细错误解析**：无论状态码是否是200，响应的数据体都可能包含错误信息，需要统一通过解析器进行详细的错误处理。

### 实现步骤

1. **统一的错误处理流程**：无论是状态码错误，还是响应体错误，都应该通过同一套 `ErrorParser` 机制来解析错误。

2. **分阶段错误处理**：

   * 第一阶段是通过状态码直接判断错误，若状态码不为 200，则认为是错误。
   * 第二阶段是通过 `ErrorParser` 来进一步解析响应体的错误信息，无论状态码是否200。

### 代码实现

#### 1. **`ResponseParser` 更新**

更新后的 `ResponseParser` 接口同时处理状态码错误和数据错误解析，统一通过 `parseError` 进行错误解析。

```typescript
import { HttpResponse, HttpError } from '../core/types';

export interface ResponseParser {
  // 解析状态码错误，返回 HttpError 或 null
  parseStatusCodeError(response: HttpResponse): HttpError | null;

  // 解析响应体中的业务错误，返回 HttpError 或 null
  parseError(response: HttpResponse): HttpError | null;

  // 提取数据
  extractData(response: HttpResponse): any | null;

  // 判断是否是 JSON 响应
  isJsonResponse(response: HttpResponse): boolean;
}
```

#### 2. **`ResponseParserFactory` 更新**

`ResponseParserFactory` 现在需要分两步处理错误：首先根据状态码判断是否是错误，然后通过 `parseError` 处理响应体中的具体错误。

```typescript
import { ResponseParser } from './ResponseParser';
import { HttpResponse, HttpError } from '../core/types';
import { ResponseParserPipeline } from './ResponseParserPipeline';

export class ResponseParserFactory {
  private static pipeline = new ResponseParserPipeline();

  // 注册自定义解析器
  static registerParser(parser: ResponseParser): void {
    this.pipeline.addParser(parser);
  }

  // 解析错误和数据
  static parseResponse(response: HttpResponse): { error: HttpError | null, data: any } {
    // 第一阶段：根据状态码判断错误
    const statusCodeError = this.pipeline.parseStatusCodeError(response);
    if (statusCodeError) {
      return { error: statusCodeError, data: null };
    }

    // 第二阶段：解析响应体中的错误
    const error = this.pipeline.parseError(response);
    if (error) {
      return { error, data: null };
    }

    // 判断是否为 JSON 格式并提取数据
    const isJson = this.pipeline.isJsonResponse(response);
    if (!isJson) {
      return { error: null, data: response.body };  // 如果不是 JSON，直接返回响应体
    }

    const data = this.pipeline.extractData(response);
    return { error: null, data };  // 返回提取的数据
  }
}
```

#### 3. **`ResponseParserPipeline` 更新**

`ResponseParserPipeline` 会按顺序执行所有解析器，首先通过 `parseStatusCodeError` 判断是否有状态码错误，然后再通过 `parseError` 判断响应体中的错误。

```typescript
import { ResponseParser } from './ResponseParser';
import { HttpResponse, HttpError } from '../core/types';

export class ResponseParserPipeline {
  private parsers: ResponseParser[] = [];

  // 向管道中添加解析器
  addParser(parser: ResponseParser): void {
    this.parsers.push(parser);
  }

  // 解析状态码错误
  public parseStatusCodeError(response: HttpResponse): HttpError | null {
    for (const parser of this.parsers) {
      const error = parser.parseStatusCodeError(response);
      if (error) {
        return error;  // 如果某个解析器处理了状态码错误，立即返回
      }
    }
    return null;  // 如果没有状态码错误，返回 null
  }

  // 解析响应体错误
  public parseError(response: HttpResponse): HttpError | null {
    for (const parser of this.parsers) {
      const error = parser.parseError(response);
      if (error) {
        return error;  // 如果某个解析器处理了错误，立即返回
      }
    }
    return null;  // 如果没有错误，返回 null
  }

  // 提取数据
  public extractData(response: HttpResponse): any {
    for (const parser of this.parsers) {
      const data = parser.extractData(response);
      if (data !== null) {
        return data;  // 如果某个解析器提取到了数据，立即返回
      }
    }
    return null;  // 如果没有数据，返回 null
  }

  // 判断是否是 JSON 响应
  public isJsonResponse(response: HttpResponse): boolean {
    const contentType = response.headers['Content-Type'] || '';
    return contentType.includes('application/json');
  }
}
```

#### 4. **具体的解析器实现**

具体的 `ResponseParser` 实现会同时处理状态码错误和响应体中的错误。

```typescript
import { ResponseParser } from './ResponseParser';
import { HttpResponse, HttpError } from '../core/types';

export class JsonResponseParser implements ResponseParser {
  // 解析状态码错误
  parseStatusCodeError(response: HttpResponse): HttpError | null {
    if (response.statusCode < 200 || response.statusCode >= 300) {
      return new HttpError(response.statusCode, `HTTP Error ${response.statusCode}`, response.body);
    }
    return null;
  }

  // 解析响应体中的业务错误
  parseError(response: HttpResponse): HttpError | null {
    if (this.isJsonResponse(response)) {
      const body = response.getBody();
      if (body.errorCode || body.code || body.errorMessage || body.msg) {
        return new HttpError(response.statusCode, body.errorMessage || 'Unknown error', body);
      }
    }
    return null;
  }

  // 提取数据
  extractData(response: HttpResponse): any | null {
    if (this.isJsonResponse(response)) {
      const body = response.getBody();
      if (body && body.data) {
        return body.data;  // 提取 data 字段
      }
    }
    return null;  // 如果没有数据，返回 null
  }

  // 判断是否是 JSON 响应
  isJsonResponse(response: HttpResponse): boolean {
    return response.headers['Content-Type']?.includes('application/json') ?? false;
  }
}
```

### 5. **`HttpClient` 更新**

`HttpClient` 通过 `ResponseParserFactory` 解析响应。根据状态码和响应体的内容，返回错误或数据。

```typescript
import { HttpRequest, HttpResponse } from './types';
import { ResponseParserFactory } from '../pipeline/ResponseParserFactory';
import { HttpTransport } from '../transport/HttpTransport';

export class HttpClient {
  constructor(
    private transport: HttpTransport,
    private middleware: Function[] = []
  ) {}

  public async request(request: HttpRequest): Promise<any> {
    const modifiedRequest = this.applyMiddleware(request);
    const response = await this.transport.send(modifiedRequest);

    // 使用 ResponseParserFactory 解析响应
    const { error, data } = ResponseParserFactory.parseResponse(response);

    if (error) {
      throw error;  // 如果有错误，抛出错误
    }

    return data;  // 返回提取的数据
  }

  private applyMiddleware(request: HttpRequest): HttpRequest {
    // 这里可以依次执行中间件
    return request;
  }
}
```

### 总结

1. **错误处理分为两个阶段**：

   * **状态码错误处理**：通过 `


parseStatusCodeError` 判断状态码错误。

* **响应体错误处理**：通过 `parseError` 解析响应体中的错误。

2. **统一的错误解析机制**：通过 `ResponseParser` 统一处理状态码错误和响应体错误，提高代码的可维护性。

3. **管道执行**：`ResponseParserPipeline` 管理多个解析器，顺序执行错误处理和数据提取。
