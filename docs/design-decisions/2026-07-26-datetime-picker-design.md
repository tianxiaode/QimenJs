# 日期时间选择器设计决策

> 日期：2026-07-26
> 状态：当前有效

## 背景

传统日期时间选择器存在以下核心痛点：

| 痛点 | 传统方案 | 本方案 |
| :--- | :--- | :--- |
| 年份大幅跳跃（2026→1899） | 点 127 次"上一年" | 点 4 次数字 |
| 时间精确到分/秒 | 滚轮滑动，易滑过头 | 数字矩阵，点击即达 |
| 日期和时间分开选 | 两个独立控件，流程割裂 | 统一入口，流程自动流转 |
| 空间占用 | 全屏弹窗，遮挡上下文 | 下拉浮层，保留预览 |

## 决策 1：统一入口 + 自动流转

**决策**：预览栏显示完整日期时间，单击任意字段进入对应选择面板，选完自动流转到下一字段。

**流转链条**：

```
年 → 月 → 日 → 时 → 分 → 秒 → 自动关闭
```

| 入口 | 执行流程 |
| :--- | :--- |
| 单击「年份」 | 年份 → 月份 → 日期 → 小时 → 分钟 → 秒 |
| 单击「月份」 | 月份 → 日期 → 小时 → 分钟 → 秒 |
| 单击「日期」 | 日期 → 小时 → 分钟 → 秒 |
| 单击「小时」 | 小时 → 分钟 → 秒 |
| 单击「分钟」 | 分钟 → 秒 |
| 单击「秒」 | 秒（选完自动关闭） |

**理由**：自动流转消除了"选完一个字段再手动找下一个字段"的割裂感，同时支持从任意字段入口开始。

## 决策 2：导航栏三按钮 — 返回 / 上一步 / 确认

**决策**：每个选择面板顶部导航栏包含三个操作按钮：

```
┌──────────────────────────────────────────────────────────────────────────────┐
│  ← 返回    ↶ 上一步    选择月份    确认 ✓                                   │
└──────────────────────────────────────────────────────────────────────────────┘
```

| 按钮 | 功能 |
| :--- | :--- |
| `← 返回` | 放弃所有修改，恢复原值，回到主视图 |
| `↶ 上一步` | 回到上一个字段面板，保留已选值，可重新选择 |
| `确认 ✓` | 保存当前所有修改，提前结束流转，回到主视图 |

**上一步行为**：
- 回到上一个字段面板时，显示之前选择的值（非原始值），对应数字高亮
- 第一个字段（年份）时上一步按钮灰显禁用
- 年份面板回到上一步时，恢复到上次选择的状态

**理由**：
- 自动流转默认存在，但用户可能不想改后续字段，确认按钮提供提前退出的能力
- 返回按钮提供撤销所有修改的能力
- 上一步按钮提供回退重选的能力，无需从头开始

## 决策 3：能直接显示就直接显示，空间不够才拆分

**决策**：面板布局遵循统一规则——选项数少且空间足够时直接显示全部选项，选项过多时拆分为高位按钮 + 低位矩阵。

| 面板 | 选项数 | 能否直接显示 | 方案 | 点击次数 |
| :--- | :--- | :--- | :--- | :--- |
| 月份 | 12 | ✅ | 6列×2行，直接显示 | 1 |
| 日期 | 28-31 | ✅ | 7列×5-6行，直接显示 | 1 |
| 小时 | 24 | ✅ | 6列×4行，直接显示 | 1 |
| 分钟 | 60 | ❌ 太密 | 十位6按钮 + 个位2列×5行 | 2 |
| 秒 | 60 | ❌ 太密 | 十位6按钮 + 个位2列×5行 | 2 |
| 年份 | 无限 | ❌ 不可能 | 千位3按钮 + 百十个6列×5行 | 4 |

**理由**：
- 直接显示最直观，零学习成本
- 60个数字密密麻麻是心理负担，拆分后视觉清爽
- 年份范围无限，必须拆分
- 拆分模式统一：高位一行按钮 + 低位数字矩阵

## 决策 5：预览栏高亮

**决策**：当前正在修改的字段在顶部预览栏中高亮显示。

```
←  2026 年 07 月 26 日   14 : 30 : 15
    ──── 高亮 ────
```

| 状态 | 高亮字段 | 样式 |
| :--- | :--- | :--- |
| 修改年份时 | `2026` | 蓝色/下划线/加粗 |
| 修改月份时 | `07` | 蓝色/下划线/加粗 |
| 修改日期时 | `26` | 蓝色/下划线/加粗 |
| 修改小时时 | `14` | 蓝色/下划线/加粗 |
| 修改分钟时 | `30` | 蓝色/下划线/加粗 |
| 修改秒时 | `15` | 蓝色/下划线/加粗 |

**年份当前输入位**：预览栏中对应位闪烁或加下划线（如 `2_ _ _` 表示正在选千位）。

## 决策 6：日期合法性校验

**决策**：修改年份或月份后，日期自动修正，被修正字段给出视觉反馈。

| 场景 | 处理方式 |
| :--- | :--- |
| 选完月份后进入日期面板 | 日期面板自动显示该月正确天数 |
| 修改年份后日期超出范围 | 根据新年份+当前月份重新计算，日期自动修正为当月最后一天 |
| 修改月份后日期超出范围 | 日期自动修正为当月最后一天 |
| 日期被自动修正 | 预览栏中该字段短暂橙色闪烁1次，提示"此值已自动调整" |

## 决策 7：秒的显示控制

| 配置 | 行为 |
| :--- | :--- |
| 秒启用 | 流程包含秒，分钟选完自动跳转秒面板 |
| 秒禁用 | 流程不含秒，分钟选完自动关闭 |

## 决策 8：中途切换字段

**决策**：正在某个面板中时，可以单击预览栏中的其他字段切换。

```
用户正在年份面板中
    │
    用户单击预览栏中的「月份」
    │
    ├─ 年份面板关闭，年份已选内容保留
    ├─ 月份面板弹出
    └─ 流程从月份重新开始
```

## 决策 9：交互反馈

| 状态 | 视觉反馈 |
| :--- | :--- |
| 当前选中字段 | 预览栏中该字段高亮（蓝色/下划线/加粗） |
| 年份当前输入位 | 预览栏中对应位闪烁或加下划线 |
| 点击数字 | 数字短暂缩放反馈（按下→弹起） |
| 面板切换 | 旧面板淡出，新面板淡入 |
| 日期被自动修正 | 预览栏中该字段短暂橙色闪烁1次 |

## 替代方案（未采用）

| 方案 | 未采用原因 |
| :--- | :--- |
| 返回即保存，无确认按钮 | 无撤销能力，误操作无法回退 |
| 自动流转无中断机制 | 用户只想改一个字段时被迫多次返回 |
| 分钟/秒60个数字直接显示 | 9列×8行每格仅37px，不满足移动端点击要求，视觉密集心理负担大 |
| 年份千位0-9全部显示 | 千位3-9极少使用，浪费空间，视觉累赘 |
| 日期面板预览栏旁加◀ ▶切换 | 和预览栏"点击字段进面板"冲突，职责混乱 |

## 事件机制（tplEvents emits + getEventData）

所有面板组件统一采用以下事件模式：

| 事件类型 | 机制 | 示例 |
| :--- | :--- | :--- |
| 单次点击即触发 | `emits` 自动转发 + `getEventData` 提取数据 | monthSelect、hourSelect、confirm、daySelect（快捷按钮） |
| 多次点击才触发 | handler 中手动 `this.emit()` | yearSelect（4次）、minuteSelect（2次）、secondSelect（2次） |
| 导航按钮 | handler 中手动 `this.emit()` | back、prev |
| 数据形状特殊 | handler 中手动 `this.emit()` | navigate（{year, month}） |

`getEventData` 统一返回 `{ value: self._value }`，emits 机制自动调用。

子组件事件监听使用 `cmp.on()` 模式（DatePicker → 各面板），`listens` 仅用于 Bridge/Entity/Float。
